## 同時実行ジョブ数の上限と引き上げ

- デフォルトの上限: 1プロジェクトあたり 25ジョブ（同時アクティブ状態）
- 組織レベルの上限: 組織全体のクォータを管理している場合、デフォルトは組織全体で 125ジョブ
- 上限の緩和（引き上げ）について
 - この「25個」という制限は固定ではありません。Google Cloud コンソールの「クォータ」画面、または Google Cloud サポートにリクエストを送信することで、運用規模に合わせて上限を引き上げることが可能です。

- https://docs.cloud.google.com/dataflow/quotas
- https://docs.cloud.google.com/dataflow/docs/request-quotas

## 1つのジョブ内の最大ワーカーノード数

Dataflowの1ジョブあたりの最大ワーカー（Compute Engine VMインスタンス）数は、処理のタイプや構成によって以下のように定義されています。

### 標準的な最大値： 2,000 個

原則として、1つのパイプラインが自動スケーリングで作成できるワーカーのハード上限は 2,000台 です。

### 特定条件下での最大値： 4,000 個

「ワーカーのゾーンを指定しない（マルチゾーン選択を任せる）」かつ「Dataflow Shuffle（バッチ処理）または Streaming Engine（ストリーミング処理）を使用する」という条件を満たした場合、最大 4,000台 までスケールアウトが可能です。

## 最大で確保しておくべきIPレンジ

Dataflowが完全にシステム上限（2,000台または4,000台）までスケールアウトすることを想定する場合、Google Cloud VPCのサブネット仕様（システム予約で5個のIPアドレスが使えない）を考慮して、以下のIPレンジ（CIDR）を確保する必要があります。

- パターンA：最大 2,000 ワーカーを想定する場合必要なIP数
  - 2,000 + 5 (\text{予約分}) = 2,005 個
  - 推奨IPレンジ: /21 （2,048 アドレス / うち 2,043 個がワーカーで利用可能）
- パターンB：最大 4,000 ワーカー（極限状態）を想定する場合必要なIP数
  - 4,000 + 5 (\text{予約分}) = 4,005 個
  - 推奨IPレンジ: /20 （4,096 アドレス / うち 4,091 個がワーカーで利用可能）

- https://docs.cloud.google.com/dataflow/quotas
  - `Maximum number of workers per pipeline` の value
